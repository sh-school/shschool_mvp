# عقدُ المخرجات — ما يقرؤه الرصدُ (0203) ومراقبةُ الجودة (0702)

متى تقرأ هذا الملف: حين تقرّر أين تكتب الأتمتةُ نتيجتَها، وكيف يُكتشف فشلُها **وغيابُها**، وبأيّ صيغةٍ تصل قراءتُها إلى الخارطة.

## من يقرأ ماذا
| القارئ | يريد | المصدر: ميثاقُه في `tabs.json` |
|---|---|---|
| «0203 · الرصد والإنذارات» | فشلٌ أو غيابٌ الآن، بدرجة (S1 إنتاجٌ/بياناتٌ/أمن فوراً، S2 يوقف الدفع أو المعاينة، S3 بطاقة) | يقرأ `watch_once.py` و«مخرجاتِ أتمتة 0801 حين تُبنى» |
| «0702 · مراقبات الجودة» | قراءةٌ دوريّة: المؤشّرُ وقيمتُه وتاريخُه وأداتُه، لاتّجاهٍ عبر الزمن | مركزُ قيادة الجودة، والحرّاس، وبطاقاتُ المسارات |
و«0701 · الخارطة» تسجّل القراءةَ بالصيغة نفسِها («المؤشّرُ بقيمته وتاريخه وأداته» — CLAUDE.md، قسمُ الخارطة الحيّة).

## المبادئُ المشتركة (كلُّ منصّة)
1. **الغيابُ إنذار.** كلُّ أتمتةٍ تُعلن متى يُتوقَّع نجاحُها التالي، والقارئُ يُنذر إن مضى الموعدُ وهامشُه بلا نجاح. «غيرُ معلوم» ليس أخضر. المصدر: `command_center/contract.py`، `core/worker_heartbeat.py` (`MAX_AGE_SECONDS` ثلاثةُ أضعاف الدورة).
2. **آخرُ قيمةٍ سليمةٍ تبقى** عند الفشل وتُوسم قديمة؛ لا تُستبدل بفارغ فتُقرأ «صفراً». المصدر: `contract.store(ok=False)`، `core/backup_status.py`.
3. **أرقامٌ وتصنيفاتٌ ورموزُ عطلٍ ثابتة**، لا نصَّ استثناءٍ ولا نصَّ طرفٍ ثالث (عنوانُ طلب، اسمُ كاتب، رسالةُ مستخدم) ولا اسمَ شخصٍ أو رقمه.
4. **الزمنُ بإزاحته** (`2026-09-28T04:00:00+03:00`)، والتقريرُ للبشر بتوقيت الدوحة.
5. **إنذارٌ واحدٌ حيٌّ لكلّ عطل** يُحدَّث ويُغلق بأوّل نجاح — لا سيلُ رسائل.

## Celery beat ← لوحةٌ في مركز قيادة الجودة (`/command-center/`)
حين تكون الأتمتةُ مؤشّرَ صحّة: مجمِّعٌ يكتب بـ`contract.store(panel, data, ok=, err=)` مغلَّفاً `{data, fetched_at, ok, err}`:
- `data` قاموسٌ مسطَّح: `status` (`ok`/`warn`/`bad`)، و`headline` جملةٌ ثابتةٌ ≤ 120 حرفاً، و`gauge` اختياريّ 0–100، وحتّى أربعة مؤشّراتٍ `m1_l`/`m1_v`…
- القِدَم بعد `STALE_AFTER_REFRESHES` (6) دورات؛ والأحمرُ المستمرُّ دقيقتين يرسل إشعاراً داخليّاً للمطوّر (سقفٌ 12 يوميّاً) ويتكرّر كلَّ 6 س، والعودةُ إشعارٌ واحد (`command_center/alerts.py`).
- لوحةٌ جديدة = مدخلٌ في `contract.PANELS` ومجمِّعٌ في `collectors.LOCAL` أو `REMOTE` (اختبارٌ يحرس تطابقَهما).
وحين تكون عملاً على البيانات (إرسال، حذف، إنهاء): القاموسُ المعاد بالأعداد، وملخّصٌ في `AuditLog` للكتابة، وسجلُّ `logger` بمستوى INFO. وقراءةُ 0702 لها من لوحةٍ أو تقرير، لا من السجلّ الخام.

## GitHub Actions ← قضيّةٌ موسومة + ملخّصُ التشغيل + ملفُّ JSON
- الفشل: قضيّةٌ عنوانُها يبدأ ببادئةٍ ثابتة (`🔴 <اسم> FAILED`) ووسمٌ `<اسم>-failure`، تُعلَّق عليها الإخفاقاتُ التالية وتُغلق بأوّل نجاح (`monitor.yml`، `nightly.yml`). يقرؤها 0203 بـ`gh issue list --label <اسم>-failure --state open`.
- القراءة الدوريّة: JSON artifact باسمٍ فيه الـcommit واحتفاظٌ محدّد، وملخّصٌ في `$GITHUB_STEP_SUMMARY` (`identity-kpis.yml`). تقرؤه 0702 بـ`gh run download`.
- الجسرُ إلى المنصّة: ما يلزم أن يُرى في لوحةٍ يُقرأ بواجهة GitHub العامّة من مهمّة beat إلى الـcache — بلا سرٍّ ولا تعديلِ المسار (`core/backup_status.py`، `command_center/collectors/ci.py`).
- المستودعُ عامّ: القضيّةُ والملخّصُ والـartifact مقروءةٌ للجميع — لا مسارَ محلّيّ ولا اسمَ فرعٍ محلّيّ ولا بيانات.

## جدولةُ ويندوز ← ملفُّ حالةٍ + علامةُ فشلٍ + سجلٌّ مُلحَق
القائمُ اليوم: `~/.claude/backups/{LAST_STATUS.json, BACKUP_FAILED.txt, auto_backup.log}`، ويقرؤها `watch_once.py::backup_alerts` مع عمر آخر إيداع (عتبةُ `max_age_h` في `thresholds.json`).
**مقترَحٌ للتوحيد** (يحتاج إقرارَ 0203 وتعديلَ `watch_once.py` في حزمة المايسترو — غيرُ مبنيٍّ بعد): كلُّ سكربتٍ يكتب `LAST_STATUS.json` في مجلّد مخرجه بهذه الحقول (القيمُ للشكل فقط):
```json
{
  "automation": "branches-report-weekly",
  "ok": true,
  "started": "2026-10-04T06:30:02+03:00",
  "finished": "2026-10-04T06:30:41+03:00",
  "exit_code": 0,
  "counts": {"branches": 38, "review": 6},
  "err": "",
  "next_due": "2026-10-11T06:30:00+03:00",
  "grace_h": 12
}
```
و`<AUTOMATION>_FAILED.txt` يُنشأ عند الفشل (سطرُ رمزِ العطل ومسارُ السجلّ) ويُحذف عند النجاح. القارئ: `ok=false` أو علامةُ الفشل ← high؛ `now > next_due + grace_h` ← high («غائبة»)؛ ملفٌّ مفقود ← warn «غيرُ معلوم».
`err` رمزٌ قصير (`git_lock`، `gh_auth`، `disk_low`) لا نصُّ الاستثناء؛ والتفصيلُ في السجلّ المحلّيّ خارج المستودع.

## درجاتُ الإنذار (مطابقةٌ لما يستعمله 0203)
| الإشارة | درجةُ `watch_once` | تصنيفُ 0203 |
|---|---|---|
| الإنتاجُ أو النسخُ الاحتياطيّ أو الأمن: فشلٌ أو غياب | high/critical | S1 |
| main أحمر، أو أداةٌ يتوقّف عليها الدفعُ أو المعاينة | high | S2 |
| قياسٌ دوريٌّ فشل أو تأخّر | warn | S3 ← بطاقةٌ في 0204 |
| نجاحٌ طبيعيّ | لا شيء | — |
المصدر: `watch_once.py` (`severity`)، ميثاقُ 0203 (`method`).

## صيغةُ القراءة لـ0702 و0701
سطرٌ واحدٌ لكلّ قراءة: `<رمزُ المؤشّر> = <القيمة> — <تاريخُ القياس بالدوحة> — <الأداة@commit>`؛ مثالٌ بقيمٍ مختلَقةٍ للشكل فقط: `CSS-raw-bytes = 436,444 — 2026-10-04 06:31 — measure_identity_kpis.py@abc1234`. وما لم يُقَس يُكتب «غيرُ مقيس» ولا يُقدَّر. المصدر: `evidence_pack.py` («غير مقيس» بدل أن تُخترَع)، ميثاقُ 0702 («لا ادّعاءَ غيرَ مقيس»).

## أنماطٌ مضادّة
- مخرجٌ يقول «تمّ» بلا أعداد، أو يكتب نصَّ الاستثناء كاملاً (قد يحمل مساراتٍ وقيماً).
- إنذارٌ عند النجاح (ضجيجٌ يُعلِّم تجاهلَ الإنذارات).
- لوحةٌ تُرسم «سليمة» حين لم يُجمَع شيءٌ بعد.
- قضيّةٌ جديدةٌ لكلّ فشلٍ بدل التعليق على المفتوحة.
- كتابةُ مخرجاتٍ محلّيّةٍ (أسماءُ فروعٍ أو أشجار) في قضيّةٍ على المستودع العامّ.
