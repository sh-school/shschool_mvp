# الأداءُ في الواجهة — الميزانيّاتُ الحيّة وما يستهلكها

متى تقرأ هذا الملف: حين تضيف صورةً أو خطّاً أو سكربتاً أو ورقةَ أنماط أو عاملَ خدمة، أو تقترب من سقف، أو تسأل «لماذا لا يظهر تعديلي؟».

المصادر: كتاب «Designing for Performance» (Lara Hogan) للمبادئ؛ `tests/web_vitals.py:BUDGET` و`tests/test_web_vitals_budget.py`، `tests/test_css_budget.py`، ADR-0005 D2، `docs/governance/regression_guards.md` (السقوف)، `CLAUDE.md` (كسرُ الذاكرة، عاملُ الخدمة، > 300ms).

## الميزانيّاتُ (القيمُ من الملفّات، 2026-09-28)
| المقياس | السقف | ملاحظة |
|---|---|---|
| CLS | ≤ 0.1 | الأبعادُ على الصور وحجزُ مكان المحتوى الديناميكيّ |
| LCP | ≤ 2500ms | |
| INP | ≤ 300ms | الكتبُ تقول 200 «جيد»؛ سقفُ المشروع 300 |
| CSS خامّ | ≤ 470KB | يشمل التعليقات (العربيّة بايتان) |
| CSS مصغَّر | ≤ 269KB | ما يصل المتصفّح |
| JS · خطوط · صور | 400 · 120 · 220 KB | |
| طلبات | ≤ 40 | |
| أوراقُ أنماطٍ حاجبة | ≤ 10 | كلُّ ملفّ CSS جديدٍ طلبٌ حاجب — يُقرَّر لا يُضاف |
- تعمل في وظيفة `axe-a11y` بـChromium حقيقيّ؛ وLighthouse الجوال ليليٌّ لا حاجب (`nightly.yml`).
- أسبابُ كلّ رقمٍ مكتوبةٌ فوقه في `BUDGET` — مقيسٌ لا «ما تحتمله الأجهزة». وأرقامُ «Dashboard < 800KB، جوال < 500KB» في الإصدار السابق من هذه المهارة من كتابٍ لا من المشروع.

## الصور
- كلُّ `<img>` في صفحات المنصّة يحمل `width` و`height` (تلميحُ نسبة)، والمقاسُ في CSS الصنف؛ وإن حدّد الصنفُ بُعداً فالآخرُ `auto` (`tests/test_img_dimensions.py`).
- `loading="lazy"` لما تحت الطيّ، و`fetchpriority="high"` لصورة LCP وحدَها.
- الأيقوناتُ من `sprite.svg` المبصوم (يُطلب مرّةً ويُخبَّأ) لا صورٌ ولا SVG مضمَّنٌ متكرّر.
- الصورُ المرفوعة يصغّرها الخادمُ عند الحفظ (`core/photo_privacy.py::clean_photo`) — لا تعِد تصغيرَها في المتصفّح.

## الخطوط
- Tajawal WOFF2 محلّيٌّ بثلاثة أوزان، `font-display: swap`، و`unicode-range` للعربيّة، ومسبقُ التحميل للعاديّ والعريض في `base.html`.
- وزنٌ رابعٌ أو عائلةٌ جديدة تستهلك سقفَ الخطوط (120KB) — قرار.

## السكربتات
- `defer` لكلّ سكربتٍ في الغلاف (HTMX مثالاً)؛ لا سكربتٌ حاجبٌ في `<head>` إلّا المبكّرين الصغيرين (الوضعُ الليليّ ولوحةُ الرسوم) بـ`nonce`.
- مكتبةٌ خارجيّةٌ جديدة: CSP الإنتاج يقبل `cdn.jsdelivr.net` و`unpkg.com` فقط، وتستهلك سقفَ JS — الأصلُ ملفٌّ محلّيّ.
- عمليّةٌ > 300ms في الطلب تذهب إلى مهمّةٍ خلفيّة (قاعدةُ المشروع؛ التصديرُ مثالُها الحيّ في `core/exports/`).

## التخزينُ المؤقّت
- الإنتاج: `CompressedManifestStaticFilesStorage` يبصم الاسمَ بمحتواه، و`core/static_storage.py` يصغّر CSS بـ`rcssmin` عند `collectstatic`؛ Brotli/gzip من WhiteNoise.
- التطوير: `max-age=0` (`development.py`) — حدِّث الصفحة وحسب، لا `?v=N` (أُزيل من 14 موضعاً) ولا `collectstatic`.
- عاملُ الخدمة لا يخدم أصلاً غيرَ مبصومٍ من ذاكرته أوّلاً (`tests/test_sw_cache_policy.py`)؛ وتغييرُ **منطقه** يرفع رقمَ `CACHE_NAME` صراحةً (`schoolos-global-v2` في `templates/pwa/sw_global.js`، `schoolos-parents-v3` في `templates/parents/pwa/sw.js`).
- `{% static '…' %}` يشير إلى ملفٍّ موجود وإلّا سقطت الصفحةُ بـ500 في الإنتاج وحده (`tests/test_static_references_exist.py`).
- وثيقةٌ ثابتة (لائحة، نموذجٌ فارغ) ملفٌّ في `static/docs/` لا قالبٌ يُولَّد كلَّ طلب (ذاكرة `feedback_performance_static.md`).

## القياس
- محلّيّاً: DevTools/Lighthouse للاتّجاه، والحكمُ لوظيفة CI. خذ الوسيطَ من عدّة تشغيلات.
- الميدانيّ: `static/js/rum.js` بثمانية حقولٍ بلا هويّة، **مطفأٌ افتراضاً حتى موافقة الـDPO** — زيادةُ حقلٍ تحتاج موافقتَه (`tests/test_rum_client.py`).

## أنماطٌ مضادّة
- `<link rel="stylesheet">` جديدٌ في قالب، أو `@import` في CSS.
- صورةٌ بلا أبعاد، أو خلفيّةٌ ضخمةٌ بـCSS لزينة.
- رفعُ `BUDGET` في الطلب الذي تجاوزه.
- تعديلُ منطق عامل الخدمة دون رفع `CACHE_NAME`، أو رفعُه لتعديل أصلٍ مبصوم.
- `?v=` أو `collectstatic` «ليظهر التعديل».
