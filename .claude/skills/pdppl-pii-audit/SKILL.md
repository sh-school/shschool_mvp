# مدقّق PDPPL لـ SchoolOS

> منصة حكومية قطرية تحوي بيانات قُصّر وبيانات صحية = **بيانات ذات طبيعة خاصة** (PDPPL م.16).
> أي تسريب أو تخزين صريح لهذه البيانات = مخالفة قانونية + مخاطرة على أطفال. الحذر إلزامي.

المسار الوحيد: `D:\shschool_mvp` مباشرة.

---

## 1. ابدأ بالفاحص الآلي

```bash
python .claude/skills/pdppl-pii-audit/scripts/pii_scan.py            # فحص شامل
python .claude/skills/pdppl-pii-audit/scripts/pii_scan.py --app clinic
python .claude/skills/pdppl-pii-audit/scripts/pii_scan.py --serializers-only
```

الفاحص يكشف بشكل استدلالي: (أ) حقول models تحمل أسماء PII وليست مشفّرة، (ب) serializers تعرض
حقول PII، (ج) سطور logging/print تطبع PII. **النتائج مرشّحات لا أحكام** — راجع كل بند بوعي
السياق. للتفاصيل القانونية والتعيينات: اقرأ `references/pdppl-map.md`.

## 2. البنية القائمة في المشروع — استخدمها، لا تعِد اختراعها

| الغرض | المكوّن الفعلي | ملاحظة |
|------|----------------|--------|
| تشفير حقل | `core.fields.EncryptedTextField` | يشفّر/يفكّ تلقائياً عبر `from_db_value`/`get_prep_value` |
| تشفير يدوي | `encrypt_field` / `decrypt_field` في `core/models/_crypto.py` | MultiFernet — يدعم تدوير المفاتيح |
| بحث دون فك تشفير | `hmac_field` | فهرس HMAC للبحث عن قيمة مشفّرة (مثل national_id) |
| تدوير المفاتيح | `FERNET_KEY` + `FERNET_OLD_KEYS` + `manage.py rotate_fernet_key` | fail-closed في الإنتاج |
| سجل تدقيق غير قابل للتعديل | `AuditLog` (`core/models/audit.py`) | manager يمنع UPDATE/DELETE |
| الموافقة | `ConsentRecord` | م.2 PDPPL — المعالجة تتطلب موافقة |
| الحق في المحو | `ErasureRequest` + `api/views_erasure.py` | م.4 — حق صاحب البيان |
| إخطار الخرق | `BreachReport` + تطبيق `breach/` | م.14 — إخطار الجهة المختصة والمتأثرين |

**القاعدة الذهبية**: كل بيان شخصي حسّاس جديد يجب أن يمرّ عبر `EncryptedTextField` أو ثلاثية
(خام مقيّد + `_encrypted` + `_hmac`) كما في `national_id`/`phone` في `core/models/user.py`.

## 3. تصنيف البيانات (طبّقه على كل حقل جديد)

### 🔴 بيانات ذات طبيعة خاصة (PDPPL م.16) — تشفير إجباري + تقييد وصول صارم
الصحة (`clinic.HealthRecord`: الحساسية، الأمراض المزمنة، الأدوية، فصيلة الدم)، البيانات
النفسية/السلوكية الحسّاسة، أي بيان دِيني/عِرقي. هذه بيانات **أطفال** → أعلى مستوى حماية.

### 🟠 بيانات تعريف شخصية (PII) — تشفير + تقييد
`national_id` (الرقم الشخصي)، `phone`، العنوان، تاريخ الميلاد، جواز/إقامة، بيانات ولي الأمر،
البريد الشخصي، الصور الشخصية.

### 🟢 بيانات تشغيلية — ضوابط وصول عادية (RBAC) دون تشفير حقل
الاسم المعروض داخل النظام، الصف، المادة، الدرجات المجمّعة، الحضور — تُحمى بالصلاحيات لا بالتشفير.

## 4. الأخطاء الشائعة التي يصطادها التدقيق

1. **حقل PII نصّي صريح**: `phone = models.CharField(...)` بلا `_encrypted`/`_hmac` مرافق.
   العلاج: أضِف الثلاثية أو حوّله إلى `EncryptedTextField`، واملأ عبر أمر إدارة مثل
   `populate_phone_encryption` (لا SQL خام).
2. **تسريب في serializer**: إدراج `national_id`/`phone`/حقل صحي في `fields = [...]` لمن لا يملك
   صلاحية. راجع `api/serializers.py`: `UserBriefSerializer` يعرض national_id/phone —
   تأكد أنّ الـ permission (`IsTeacherOrAdmin` وأمثاله) يبرّر ذلك، ووفّر `UserSafeSerializer`
   (الاسم فقط) للسياقات العامة.
3. **PII في السجلّات**: `logger.info(f"... {user.national_id}")` يكتب PII في ملفات نصية غير
   مشفّرة. سجّل مُعرّف UUID فقط، لا القيمة الحسّاسة. (`AXES_SENSITIVE_PARAMETERS` يخفي كلمة
   المرور — طبّق نفس المبدأ يدوياً على PII.)
4. **معالجة بلا موافقة**: تدفّق جديد يجمع بياناً شخصياً دون تسجيل `ConsentRecord` أو أساس
   قانوني. م.2 PDPPL تشترط موافقة صريحة (أو استثناءً قانونياً موثّقاً).
5. **محو ناقص**: `ErasureRequest` يحذف الصف الأصلي لكن ينسى النسخ في السجلّات/التقارير/الـ
   backups. وثّق نطاق المحو، مع الإبقاء على `AuditLog` (سجل قانوني غير قابل للحذف — قيّد لا تمحُ).
6. **تخزين أسرار في الواجهة**: أي token/سر في `localStorage` ممنوع (معيار المشروع). استخدم
   كوكيز آمنة فقط + تدوير refresh (SIMPLE_JWT `ROTATE_REFRESH_TOKENS=True` مضبوط بالفعل).

## 5. قائمة تحقّق الامتثال (قبل الموافقة على PR يمسّ بيانات شخصية)

- [ ] كل حقل 🔴/🟠 جديد مشفّر (`EncryptedTextField` أو ثلاثية HMAC).
- [ ] لا يظهر حقل PII في serializer/قالب إلا خلف permission مبرّر؛ يوجد بديل «آمن» بالاسم فقط.
- [ ] لا PII في `logger`/`print`/رسائل الأخطاء — UUID فقط.
- [ ] التدفّق يسجّل `ConsentRecord` أو يوثّق الأساس القانوني.
- [ ] الوصول للبيانات الصحية مقصور على الأدوار المخوّلة (ممرضة/قيادة) عبر RBAC + object permission.
- [ ] أي جمع بيانات جديد ينعكس في مسار `ErasureRequest` (المحو يشمله).
- [ ] `FERNET_KEY` مضبوط في الإنتاج (fail-closed)؛ خطة تدوير المفاتيح موثّقة.
- [ ] عملية عالية الخطورة تُقيَّم بثالوث CIA (سرّية/سلامة/توافر) وتُسجَّل في `AuditLog`.
