# التعافي — وماذا تفعل حين ترى شيئاً غريباً

متى تقرأ هذا الملف: حين يُظهر `git status` ما لم تتوقّعه، أو ضاع إيداع، أو علقت إعادةُ أساس، أو رُفض دفع، أو
أُغلق طلبُك فجأة، أو اختفى فرع.

القاعدةُ الأولى: **لا تُصلح بأمرٍ هدّام**. كلُّ ما هنا إضافةٌ أو قراءة؛ وما يحتاج حذفاً يُسلَّم للمالك أو لأمين
المستودع بأدلّته.

## 1) `git status` فيه ما لم تتوقّعه

| ما تراه | معناه الأرجح في هذا المشروع | ما تفعله |
|---|---|---|
| ملفٌّ معدَّلٌ أو جديدٌ لم تلمسه | عملُ جلسةٍ أخرى (مهمّةٌ خلفيّةٌ لها ظهر أثرُها في شجرتك، أو صدفةُ المالك) | **قِف واسأل** المالكَ أو المايسترو. لا `add` ولا `checkout` ولا حذف. المصدر: CLAUDE.md البند 5؛ ذاكرة feedback_parallel_sessions (شاهدا 08-28 و09-08) |
| ` M` على ملفٍّ ولا فرقَ في `git diff --ignore-cr-at-eol` | نهاياتُ أسطر (CRLF) من أداةٍ على ويندوز | لا تودِعه وحدَه؛ `.gitattributes` يفرض LF لـ`*.py` عند الإيداع. تحقّق: `git ls-files --eol <مسار>`. المصدر: ذاكرة project_rep10_prune_by_content |
| `.claude/settings.local.json` معدَّل | أذوناتُ الجلسة المحلّيّة؛ صار غيرَ متتبَّعٍ ومتجاهَلاً في main | في شجرةٍ أساسُها قديم: انسخه جانباً، `git checkout -- .claude/settings.local.json`، ادمج main، أعِده. لا stash. المصدر: صفُّ REP-11 في `docs/governance/regression_guards.md` |
| «rebase in progress» / «You have unmerged paths» | عمليّةٌ لم تكتمل (قد تكون من أمرٍ سابقٍ لك) | أكملها أو `git rebase --abort` / `git merge --abort`. لا دفعَ قبل ذلك. المصدر: ذاكرة feedback_check_rebase_before_push |
| `HEAD detached` | رأسٌ منفصل (شجرةٌ مؤقّتة أو checkout لإيداع) | لا تودِع عليه عملاً؛ أنشئ فرعاً `git switch -c claude/<اسم>` في شجرتك أنت |
| الفرعُ غيرُ ما تظنّ، أو إيداعاتُك «اختفت» | أحدٌ بدّل الفرعَ أو شغّل reset في هذه الشجرة | `git reflog show <فرعك>` و`git reflog` ثمّ §2 |
| ملفُّ `_شيء.py` كتبتَه ولا يظهر | يتجاهله `.gitignore` (`_*.py`) | سمِّه بلا `_`؛ `git check-ignore -v <مسار>`. المصدر: ذاكرة feedback_gitignore_underscore_modules |
| لقطاتٌ ومخرجاتُ قياسٍ لك تملأ القائمة | ملفّاتُ أدواتٍ داخل الشجرة | انقلها إلى `C:/Users/<المستخدم>/<اسمك>_work/`؛ لا `.git/info/exclude`. المصدر: ذاكرة feedback_scratchpad_wiped_mid_session |
| في الجذر `D:\shschool_mvp`: فرعُ ميزةٍ قديمٌ وعشراتُ غيرِ المتتبَّع | حالةٌ تنتظر قرارَ المالك، وحاوياتُ القاعدة تعمل منه | لا تلمس الجذرَ من جلسة شجرة. المصدر: docs/archive_survey_2026-09-28.md (حزمة المايسترو) |

سكربتُ `scripts/git_preflight.py` يطبع المدخلاتِ كلَّها ويعلّم ما هو CRLF فقط وما يتجاهله `.gitignore`.

## 2) إيداعٌ ضاع أو فرعٌ اختفى

الاسترجاعُ **إضافةٌ لا حذف**: أنشئ فرعاً جديداً على الإيداع المفقود، ولا تحرّك فرعاً قائماً بـreset.

```bash
git reflog show <الفرع>                  # أين كان الطرفُ قبل أن يتحرّك
git branch claude/<اسم>-restored <sha>    # فرعٌ جديدٌ على الإيداع — لا reset --hard
```

- الأداةُ المركزيّة تطبع لكلّ فرعٍ حذفته سطرَ استرجاعه (`git branch <الاسم> <الطرف>`)، وما وسمته يُسترجع من
  وسمه: `git branch <الاسم> archive/<الاسم>-<التاريخ>`. المصدر: `scripts/prune_local_branches.py` (`_render_actions`، `SAFE_TAGGED`).
- ليلاً تُحفظ حزمةُ `git bundle --all` للمستودع خارجه (مكانُها وجدولتُها في ذاكرة project_git_roadmap_integration، REP-01):
  تحمل كلَّ المراجع ولا تحمل غيرَ المودَع. الاستعادةُ منها قرارُ المالك أو أمين المستودع.
- إيداعاتٌ كانت محلّيّةً فقط وسقطت بـreset من صدفةٍ أخرى استُعيدت من قبلُ بتجزئاتها (المسجَّلة في ذاكرة الجلسة) —
  **ولهذا سجّل تجزئةَ كلّ إيداعٍ مهمٍّ في تقريرك**. المصدر: ذاكرة feedback_parallel_sessions (2026-09-11).
- ما لم يُودَع قطّ وأُزيلت شجرتُه لا يُسترجع. المصدر: ذاكرة project_git_roadmap_integration (شجرتان أُزيلتا 09-25).

## 3) إعادةُ أساسٍ علقت، أو دُفع رأسٌ خاطئ

- توقّفت إعادةُ الأساس على تعارضٍ في إيداعاتٍ دُمجت بالسحق: `git rebase --abort`، ثمّ `git rebase --onto origin/main
  <آخرُ إيداعٍ من الطلب المدموج>` (فرعٌ لم يُدفع)، أو `git merge origin/main` (فرعٌ منشور).
- دُفع رأسٌ يساوي main فأُغلق الطلبُ تلقائيّاً (#277): العملُ ما زال في فرعك المحلّيّ؛ بعد `rebase --abort` تأكّد أنّ
  `git log origin/main..HEAD` غيرُ فارغ ثمّ ادفع إلى الاسم نفسِه دفعاً تقدّميّاً وأعِد فتحَ الطلب أو افتح غيرَه.
المصدر: ذاكرة feedback_check_rebase_before_push.
- أعدتَ أساسَ فرعٍ **منشور** فرُفض الدفعُ (non-fast-forward): لا force. ابنِ على النسخة المنشورة في شجرتك أنت —
  `git switch -c claude/<اسم>-sync origin/claude/<اسم>` ثمّ `git merge origin/main` وحلُّ التعارض ثمّ
  `git push origin HEAD:refs/heads/claude/<اسم>` (دفعٌ تقدّميّ إلى الاسم نفسِه)؛ ويبقى الفرعُ المعاد أساسُه محلّيّاً
  للمقارنة. المصدر: الحارس (push-force)، وذاكرة project_git_roadmap_integration (#604: الدمجُ لا إعادةُ الأساس للمنشور).

## 4) الدفعُ رُفض

| الرسالة | السبب | الإجراء |
|---|---|---|
| `GH006 … added to a merge queue` | الطلبُ في طابور الدمج فالفرعُ مقفل | لا تُخرجه؛ أبلغ «0601 · النشر على الإنتاج والدمج». المصدر: ذاكرة feedback_merge_queue_branch_lock |
| `rejected … (fetch first)` / non-fast-forward | على الفرع البعيد إيداعاتٌ ليست عندك | `git fetch` ثمّ `git merge origin/claude/<اسم>` ثمّ دفعٌ تقدّميّ. لا force |
| `protected branch hook declined` | وجهةٌ محميّة (main، أو فرعٌ في الطابور) | راجع الوجهة؛ إلى `claude/…` وحدَه |
| «محجوب بحارس الغيت (REP-19)» | قاعدةٌ في الحارس | `01-forbidden-and-why.md` |

## 5) الإيداعُ فشل

- أوّلَ مرّة بعد تعديل الخطّاف للملفّ (مسافاتٌ زائدة، نهايةُ ملفّ، ruff --fix): `git add` للمسارات نفسِها ثمّ أعِد
  الإيداع. المصدر: ذاكرة feedback_windows_shell_classifier_pitfalls.
- `detect-secrets` اعترض على قيمةٍ في اختبار: تأكّد أوّلاً أنّها وهميّةٌ فعلاً؛ والاستثناءُ لسطرٍ بعينه قرارٌ يُذكر
  في وصف الطلب (سابقة #636)، لا إسكاتٌ للخطّاف كلِّه. المصدر: ذاكرة project_git_roadmap_integration.
- `check-added-large-files` (أكثرُ من 500KB): الملفُّ لا مكانَ له في مستودعٍ عامّ على الأرجح؛ اسأل قبل أن تلتفّ.

## 6) دمجٌ من main أعاد شيئاً إلى الوراء

بعد حلّ تعارض: `git diff origin/main...HEAD` يُظهر ملفّاً لا علاقة له بمهمّتك أو حذفاً لم تقصده ← حلُّك اختار نسختك
القديمة. أعِد الملفَّ من main بإيداعٍ جديد (`git checkout origin/main -- <مسار>` ثمّ طبّق تغييرك عليه إن وُجد) ثمّ
أودِع. المصدر: ذاكرة feedback_verify_actual_diff_before_enqueue (#715 ألغى #709 بصمت).

## 7) بعد نافذة إعادة كتابة التاريخ (U-03)

خطّةُ إصلاح غيت تتضمّن نافذةً تُعاد فيها كتابةُ تاريخ المستودع (موعدُها المعلَن في الذاكرة الجمعة 2026-10-02؛
تحقّق من الخارطة الحيّة). بعدها **لا يُدفع أيُّ فرعٍ محلّيٍّ مبنيٍّ على التاريخ القديم** — يُعيد الكائناتِ المحذوفة إلى
GitHub. انقل عملك فوق main الجديد بتوجيه أمين المستودع. المصدر: ذاكرة project_git_roadmap_integration (REP-05/REP-06، RD3).

## أنماطٌ مضادّة

- «أصلح» حالةً غريبةً بـ`reset --hard` أو `checkout .` أو `clean -f` — تمحو دليلَ ما حدث وعملَ غيرك معاً.
- استرجاعُ إيداعٍ بتحريك فرعٍ قائم بدل فرعٍ جديد.
- إعادةُ محاولة الدفع المرفوض بإضافة `--force-with-lease` «لأنّه آمن».
- إضافةُ الملفّ المجهول إلى إيداعك «لأنّه يبدو مفيداً».
