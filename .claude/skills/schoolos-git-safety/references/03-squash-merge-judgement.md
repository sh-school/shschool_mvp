# الدمجُ بالسحق والحكمُ على «مدموج؟» — وسلامةُ إزالة الأشجار وحذف الفروع

متى تقرأ هذا الملف: قبل أن تقول عن فرعٍ أو شجرةٍ «اندمج/لم يندمج»، أو «يتيم»، أو «آمنٌ للحذف»؛ وقبل أيّ اقتراحٍ
بإزالة شجرةٍ أو حذف فرعٍ محلّيٍّ أو وسم.

## 1) لماذا تكذب الأدواتُ المعتادة هنا

طابورُ الدمج على main يدمج بالسحق (SQUASH): يصنع إيداعاً واحداً جديداً في main بتجزئةٍ وبصمةِ رقعةٍ جديدتين. فالفرعُ
المدموجُ كلُّه يبقى:
- «متقدّماً» في `git rev-list origin/main..HEAD` وفي `git log origin/main..<فرع>`؛
- «غيرَ مدموج» في `git branch --merged` و`merge-base --is-ancestor`؛
- «+» في `git cherry origin/main <فرع>` حين يكون الفرعُ أكثرَ من إيداعٍ واحد (بصمةُ المجمَّع تختلف عن بصمات أجزائه).

قيس ذلك 2026-09-28: شجرتان اندمج عملُهما (#714، #707) أُعلنتا يتيمتين؛ وفي 09-25 وُصفت خمسةُ فروعٍ حذفها المالك
«غيرَ مدموجة» وهي مدموجةٌ كلُّها بطلباتٍ مسحوقة.
المصدر: `tools/branch_status.py` في حزمة المايسترو (docstring)، وذاكرة project_git_audit_2026_09_25 (الطابور SQUASH)،
وذاكرة project_git_roadmap_integration («تصحيحُ الفروع الخمسة»).

والعكسُ صحيحٌ أيضاً: «-» في `git cherry` دليلٌ إيجابيّ (الرقعةُ في main)، لكنّ «+» ليس دليلاً على عدم الدمج.

## 2) سُلّمُ الأدلّة (من الأقوى)

هو نفسُه ما تحكم به الأداةُ المركزيّة `scripts/prune_local_branches.py` (وتحرسها `tests/test_prune_local_branches.py`):

1. **سلفٌ لـmain**: `git merge-base --is-ancestor <طرف> origin/main` — دمجٌ عاديّ.
2. **يحويه وسم**: `git tag --contains <طرف>` — غالباً `archive/<اسم>-<تاريخ>`؛ يُسترجع منه.
3. **طرفُه رأسُ طلبٍ مدموجٍ أو سلفُه**: `headRefOid` لطلبٍ `MERGED` يساوي الطرفَ أو الطرفُ سلفُه.
   ```bash
   gh pr list --head <فرع> --state all --json number,state,headRefOid,mergedAt
   git merge-base --is-ancestor <طرف> <headRefOid>
   ```
   **اسمُ الفرع وحدَه لا يكفي**: فرعٌ أُعيد استعمالُ اسمه بعد الدمج وعليه إيداعاتٌ جديدةٌ ليس مدموجاً — الإيداعاتُ فوق
   `headRefOid` عملٌ جديدٌ يحتاج طلباً جديداً (كانت هذه ثغرةَ الأداة القديمة).
4. **المحتوى في تاريخ main**: كلُّ ملفٍّ غيّره الفرعُ منذ تفرّعه موجودٌ بنسخته (blob) في تاريخ main، وكلُّ حذفٍ فعله
   وقع في main. لملفٍّ واحد: `git log -1 --find-object=<blob> origin/main`.
5. **بصمةُ الرقعة التراكميّة** تساوي بصمةَ الإيداع المسحوق:
   ```bash
   git diff $(git merge-base origin/main <طرف>) <طرف> | git patch-id --stable
   git show <sha-المسحوق> --format= | git patch-id --stable
   ```
   وعن إيداعٍ واحد: `gh api repos/{owner}/{repo}/commits/<sha>/pulls` (422 = لا يعرفه GitHub؛ فارغ = دُفع بلا طلب).

ما لا دليلَ عليه = **REVIEW**: «لم يُثبَت الدمج» لا «عملٌ فريدٌ حتماً» — ولا يُحذف آليّاً أبداً.
المصدر: `scripts/prune_local_branches.py` (docstring و`find_evidence`)، وذاكرة feedback_worktree_removal_safety_checks
البند 4، وذاكرة project_git_roadmap_integration (بصمةُ الرقعة التراكميّة).

## 3) الفخّان المعروفان في الحكم بالمحتوى

- **الملفُّ الساخن**: `docs/governance/regression_guards.md` يضيف إليه كلُّ طلبٍ صفوفاً، فيدمجه السحقُ مع صفوف غيره
  ولا يطابق blobُ الفرعِ أيَّ نسخةٍ في main ← REVIEW لفرعٍ مدموجٍ فعلاً. الدليلُ 3 (الطلب) يحسمه.
- **تعارضُ `merge-tree` ليس دليلَ فرادة**: فرعٌ مسحوقٌ ثمّ عدّل main الأسطرَ نفسَها يتعارض أيضاً.
المصدر: ذاكرة project_rep10_prune_by_content («حدودُه»)، وذاكرة project_git_roadmap_integration (REP-05 «درس»).

## 4) أدواتُ الحكم

| الأداة | ماذا تجيب | أين |
|---|---|---|
| `python .claude/skills/schoolos-git-safety/scripts/git_preflight.py --judge <فرع> --gh` | الأدلّةُ 1–4 لفرعٍ واحد، وهل هو حيٌّ في شجرة، وهل نسختُه وحيدة | هذه المهارة (قراءةٌ فقط) |
| `bash scripts/prune_local_branches.sh` (بلا `--apply`) | كلُّ الفروع المحلّيّة: SAFE_* / GRACE / REVIEW / KEEP_LIVE / KEEP_OPEN_PR | المستودع |
| `tools/branch_status.py` | حالةُ كلّ شجرةٍ بطلب فرعها (open_pr/merged/work_after_merge/no_pr…) | حزمة المايسترو (خارج المستودع) |

`--archive` في أداة الفروع يَسِم فروعَ REVIEW بوسمٍ محلّيٍّ لا يحذف ولا يدفع؛ و`--apply` يحذف — **والحارسُ يحجبه
لأنّه بيد المالك** بعد إعادة الأدلّة قبله بدقائق. المصدر: `guard_git.py` (`_prune_apply`)، `prune_local_branches.sh`.

## 5) سياسةُ الفروع (RD5) كما في الشيفرة

- مهلةُ 48 ساعةً بعد آخر إيداع قبل حذف الآمن (`GRACE_HOURS = 48`).
- سقفُ 40 فرعاً فريداً غيرَ مدموج (`REVIEW_CEILING = 40`)، ودفعةُ حذفٍ ≤ 50 (`MAX_DELETIONS = 50`).
- وسمٌ يسبق حذفَ ما لم يُدمج؛ والحذفُ مشروطٌ بأنّ الطرفَ لم يتحرّك منذ الحكم.
- فروعُ `backup-*` و`before-…-fix` لا تُوسَم آليّاً (وسمٌ يُدفع قد ينشر بياناتٍ شخصيّة).
المصدر: `scripts/prune_local_branches.py` (الثوابتُ و`ARCHIVE_SKIP` و`delete_branch`).

## 6) قبل إزالة شجرةِ عمل — قائمةُ فحص

الإزالةُ ليست عملَ جلسةٍ عاديّة: تُنفَّذ بأمر المالك، وقد أُسندت إلى أمين المستودع (سابقةُ D-24م في `decisions.md`
بحزمة المايسترو)، والحذفُ الجماعيّ يُسلَّم للمالك أوامرَ يشغّلها بيده. فإن طُلب منك تقديمُ الأوامر:

1. **حيّةٌ؟** غيابُ خادم Docker لا يعني غيابَ جلسة: افحص قائمةَ الجلسات (`cwd` لكلٍّ) وملفَّ
   `<الشجرة>/.claude/scheduled_tasks.lock` (فيه pid؛ pid ميّتٌ = قفلٌ بائت).
2. **شجرةٌ حقّاً؟** مجلّدٌ تحت `.claude/worktrees` قد يكون قوقعةً فارغة (يبقى `.venv` نقطةَ تركيب): افحص `.git`
   و`manage.py` وعددَ الملفّات، وقارن بـ`git worktree list --porcelain`.
3. **متداخلة؟** شجرةٌ داخل شجرة (`…/<شجرة>/.claude/worktrees/_tmp-x`) تخدع `basename`: خذ المسارَ الكامل، وأزل
   المتداخلةَ قبل الأصل.
4. **مدموج؟** بالسُّلّم أعلاه لا بالمانيفست ولا `branch --merged`.
5. **غيرُ المودَع؟** `git --no-optional-locks -C <شجرة> status --porcelain` وفرقُ الملفّات المعدَّلة: الحزمةُ الليليّة لا
   تحمله، فانسخه خارج المستودع قبل أيّ إزالة.
6. **محميّة؟** الجذرُ `D:\shschool_mvp` لا يُزال (حاوياتُ القاعدة وredis والصورةُ منه)، ولا أشجارُ الجلسات الحيّة
   والدائمة.
7. **الترتيبُ الآمن**: المتداخلةُ ← الأصل ← الفرع (والفرعُ بأدلّته، والفريدُ بعد وسمه).

المصدر: ذاكرة feedback_worktree_removal_safety_checks (البنود 1–5)، وذاكرة feedback_windows_shell_classifier_pitfalls
(الترتيب وتسليمُ الأوامر للمالك)، وdocs/archive_survey_2026-09-28.md (الجذر لا يُمسّ).

## 7) فرعٌ لم يُدفع قطّ

لا يعرف عنه GitHub شيئاً: إن أُعيد عملُه في فرعٍ آخر واندمج، يبقى الأصلُ محلّيّاً للأبد؛ وإن حُذف قبل أن يبلغ
محتواه main ضاع (لا نسخةَ بعيدة). فلا يُحذف إلّا بدليلٍ من السُّلّم أو بعد وسمٍ يحفظه.
المصدر: CLAUDE.md البند 6 (17 فرعاً من هذا وُجدت 2026-09-17).

## أنماطٌ مضادّة

- «الشجرةُ متقدّمةٌ على main بـ16 إيداعاً إذن فيها عملٌ معلَّق» — احكم بحالة الطلب أوّلاً.
- «له طلبٌ مدموجٌ بالاسم نفسِه إذن هو مدموج» — قارن `headRefOid` بالطرف.
- «خاملةٌ لا خادمَ لها إذن تُزال» — افحص الجلسة والقفل.
- `git branch -D` لأنّ `-d` رفض فرعاً مسحوقاً — رفضُه متوقّع، والحكمُ بالأدلّة.
- دفعُ وسم أرشيفٍ «لحفظه» — دفعُ الوسوم بإذن المالك، وبعضُها يحمل ما لا يُنشر.
