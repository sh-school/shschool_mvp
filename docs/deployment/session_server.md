# خادمُ الجلسة وقاعدتُها

> نُقل حرفيّاً من CLAUDE.md (W-20261003-006، D-158م): يلزم من يشغّل خادماً أو اختباراً أثناء عمله. خطؤه يظهر فشلَ أمرٍ لا مخالفةً صامتة، فلا يحتاج تحميلاً تلقائيّاً.

### خادمُ الجلسة

> **منذ 2026-09-25 خادمُ الجلسة عند الحاجة لا مقيماً** — الخادمُ المقيمُ الوحيدُ هو
> «المعاينةُ المركزيّة» (القسمُ بعد هذا). شغّل خادمَك لفحصك وأطفئه بعده.

مرّتان لكلّ شجرةِ عمل — `.env` متجاهَلٌ في غيت فلا يصل الشجرةَ من نفسه،
والقاعدةُ تُنسَخ لك وحدَك:

```bash
cp D:/shschool_mvp/.env .env
```

```bash
bash scripts/session-db.sh
```

ثمّ في كلّ مرّة، بمنفذٍ لم تأخذه جلسةٌ أخرى (8001، 8002، 8003…):

```bash
SESSION_DB=$(bash scripts/session-db.sh --name) WEB_PORT=8001 docker compose -p schoolos-$(basename $PWD) --project-directory . -f D:/shschool_mvp/docker-compose.session.yml up -d
```

ويقلع معه عاملُ خلفيّةٍ للشجرة (`worker`) على طابورٍ باسم قاعدتها (`SESSION_NAMESPACE`)
— فالتصديرُ والتوليدُ يعملان بكود شجرتك وقاعدتها، ولا يلتقطهما عاملُ الحزمة الأصليّة.
والعاملُ لا يُعيد تحميلَ الكود: بعد تعديل مهمّةٍ أعِد تشغيلَه بالأمر نفسِه مع `restart worker`.

و`--project-directory .` هو المفتاح: ملفُّ الإنشاء يبقى في الجذر واحداً،
والمساراتُ فيه تُحلّ على شجرتك أنت — فلا يُنسخ إلى كلّ شجرةٍ ولا يُخلّف ملفّاً
غيرَ متتبَّعٍ يمنع سحبَ الفرع لاحقاً.

### ولِمَ قاعدةٌ لكلّ شجرة

كانت الأشجارُ كلُّها على `shschool_db`. فلمّا حذف فرعٌ عموداً بهجرةٍ يومَ
2026-09-11 سقطت ثمانُ صفحاتٍ في **كلّ** شجرةٍ أخرى ساعاتٍ بـ
`column operations_subject.spread_days_scope does not exist` — وشيفرةُ تلك
الأشجار سليمةٌ لا علّةَ فيها. والخادمُ كان معزولاً والقاعدةُ وحدَها مشتركة.

فصار لكلّ شجرةٍ قاعدتُها، تُنسخ من المشتركة أوّلَ مرّة — ثمانيةٌ وستّون
ميغابايتاً في اثنتَي عشرةَ ثانية — **والهجرةُ بعدها تُطبَّق في شجرتك أنت**،
فلا تُصيب غيرَك.

ويبقى شرطٌ واحد: أن تعمل قاعدةُ الحزمة الأصليّة وredis (في `D:\shschool_mvp`)
والصورةُ المبنيّة منها — أمّا خادمُ الجذر وعاملُه (المنفذ 8000) فلا يلزمان، وقد أُوقفا
2026-09-25 توفيراً للذاكرة.

### إنهاء الجلسة

عند انتهاء عمل الشجرة أوقف خادمها ولا تتركه يستهلك الذاكرة:

```bash
docker compose -p schoolos-$(basename $PWD) --project-directory . -f D:/shschool_mvp/docker-compose.session.yml stop
```

- `stop` وحده، **لا `down -v`** ولا `docker volume prune`: وحداتُ التخزين تحمل قواعدَ بيانات. ويُعاد التشغيل بـ`up -d` أو `start`.
- `scripts/session-db.sh` لا يوفّر خيارَ حذف (خياراته الوحيدة `--name`، وبلا وسيطٍ ينشئ القاعدة إن لم توجد)؛ فقاعدةُ الشجرة المنسوخة تبقى حتى يحذفها المالك أو جلسةُ التنظيف يدوياً. لا تفترض خيار حذف ولا تنفّذ `DROP DATABASE` من عندك.
- لا تلمس `shschool-dev-db` ولا `shschool-dev-redis` ولا حاويات `schoolos-main-preview-*`.

### خلفية القاعدة رقم 1 (مُنقولة حرفياً من CLAUDE.md)

كانت القاعدةُ قبل 2026-09-08 «لا worktree أبداً» لأنّ `docker-compose.yml` يربط `- .:/app`؛ فعالجت
العَرَضَ بمنع العزل وصار رأسٌ وفهرسٌ واحدٌ لمحادثاتٍ متوازية (تبديلُ فرعٍ يسحب الأرضَ من تحت غيره، و`git add -A`
يبتلع عملَ غيره). و`docker-compose.session.yml` أزال السبب: خادمٌ لكلّ شجرةٍ على منفذها بقاعدةٍ مشتركة.

### تشغيل الاختبارات (مُنقول حرفياً من CLAUDE.md)

```bash
docker compose -p schoolos-$(basename $PWD) --project-directory . -f D:/shschool_mvp/docker-compose.session.yml exec -T web sh -c 'DJANGO_SETTINGS_MODULE=shschool.settings.testing TEST_DB_HOST=$DB_HOST TEST_DB_PORT=$DB_PORT TEST_DB_USER=$DB_USER TEST_DB_PASSWORD=$DB_PASSWORD python -m pytest <المسارات> -q -p no:cacheprovider'
```
واسمُ قاعدةِ الاختبار يُشتقّ من قاعدةِ جلستك تلقائيّاً (`test_ss_<slug>`)، فلا
تصطدم جلستان. ولو رأيتَ عشراتِ `ERROR` في **الإعداد** دفعةً واحدة فاقرأ
الرسالةَ قبل أن تتّهم تعديلك: غالبُها تصادمٌ لا عطب.

## فحصٌ موحَّدٌ قبل «جاهزٌ للمعاينة» — `make premerge` (W-20261016-020)

يجمع prepush وaffected واختباراتٍ تذكر الملفَّ المعدَّل ومحاكاةَ دمج origin/main وتداخلَ الطلبات المفتوحة، ويطبع «غير مقيس» لما لا يستطيع تشغيله. الأفضلُ داخل حاوية الجلسة (فيها المتطلّبات): `docker compose -p schoolos-$(basename $PWD) --project-directory . -f D:/shschool_mvp/docker-compose.session.yml exec -T web python scripts/premerge.py`. وضعُ الظلّ أسبوعاً: يطبع ويسجّل في `.git/premerge_shadow.jsonl` ولا يحجب؛ والإلزامُ بـ`--enforce` بعد مقارنته بفشل CI الفعليّ. المقيس على ويندوز بلا حاوية: نحو دقيقتين، وفشلُ `test_ci_gates_are_honest` فيه بيئيٌّ (أمر bash).
