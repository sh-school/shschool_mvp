# خادمُ الجلسة وقاعدتُها

> نُقل حرفيّاً من CLAUDE.md (W-20261003-006، D-158م): يلزم من يشغّل خادماً أو اختباراً أثناء عمله. خطؤه يظهر فشلَ أمرٍ لا مخالفةً صامتة، فلا يحتاج تحميلاً تلقائيّاً.

### خادمُ الجلسة

> **منذ 2026-09-25 خادمُ الجلسة عند الحاجة لا مقيماً** — الخادمُ المقيمُ الوحيدُ هو
> «المعاينةُ المركزيّة» (القسمُ بعد هذا). شغّل خادمَك لفحصك وأطفئه بعده.

مرّتان لكلّ شجرةِ عمل — `.env` متجاهَلٌ في غيت فلا يصل الشجرةَ من نفسه،
والقاعدةُ تُنسَخ لك وحدَك:

```bash
cp D:/shschool_mvp/.env .env
```

```bash
bash scripts/session-db.sh
```

ثمّ في كلّ مرّة، بمنفذٍ لم تأخذه جلسةٌ أخرى (8001، 8002، 8003…):

```bash
SESSION_DB=$(bash scripts/session-db.sh --name) WEB_PORT=8001 docker compose -p schoolos-$(basename $PWD) --project-directory . -f D:/shschool_mvp/docker-compose.session.yml up -d
```

ويقلع معه عاملُ خلفيّةٍ للشجرة (`worker`) على طابورٍ باسم قاعدتها (`SESSION_NAMESPACE`)
— فالتصديرُ والتوليدُ يعملان بكود شجرتك وقاعدتها، ولا يلتقطهما عاملُ الحزمة الأصليّة.
والعاملُ لا يُعيد تحميلَ الكود: بعد تعديل مهمّةٍ أعِد تشغيلَه بالأمر نفسِه مع `restart worker`.

و`--project-directory .` هو المفتاح: ملفُّ الإنشاء يبقى في الجذر واحداً،
والمساراتُ فيه تُحلّ على شجرتك أنت — فلا يُنسخ إلى كلّ شجرةٍ ولا يُخلّف ملفّاً
غيرَ متتبَّعٍ يمنع سحبَ الفرع لاحقاً.

### ولِمَ قاعدةٌ لكلّ شجرة

كانت الأشجارُ كلُّها على `shschool_db`. فلمّا حذف فرعٌ عموداً بهجرةٍ يومَ
2026-09-11 سقطت ثمانُ صفحاتٍ في **كلّ** شجرةٍ أخرى ساعاتٍ بـ
`column operations_subject.spread_days_scope does not exist` — وشيفرةُ تلك
الأشجار سليمةٌ لا علّةَ فيها. والخادمُ كان معزولاً والقاعدةُ وحدَها مشتركة.

فصار لكلّ شجرةٍ قاعدتُها، تُنسخ من المشتركة أوّلَ مرّة — ثمانيةٌ وستّون
ميغابايتاً في اثنتَي عشرةَ ثانية — **والهجرةُ بعدها تُطبَّق في شجرتك أنت**،
فلا تُصيب غيرَك.

ويبقى شرطٌ واحد: أن تعمل قاعدةُ الحزمة الأصليّة وredis (في `D:\shschool_mvp`)
والصورةُ المبنيّة منها — أمّا خادمُ الجذر وعاملُه (المنفذ 8000) فلا يلزمان، وقد أُوقفا
2026-09-25 توفيراً للذاكرة.
