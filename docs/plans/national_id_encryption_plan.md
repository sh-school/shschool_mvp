# خطة تشفير `national_id` at-rest — هجرة مُتدرّجة آمنة

> الحالة: **مُقترَح للمراجعة** — لا يُنفَّذ على عجل (يمسّ تسجيل الدخول لكل المستخدمين).

## 1. الوضع الحالي (مبنيّ على `core/models/user.py`)
- `national_id` = `CharField(unique, db_index)` **نصّ صريح**، وهو `USERNAME_FIELD`.
- موجود أصلاً: `national_id_encrypted` (Fernet) + `national_id_hmac` (`db_index`، **ليس** `unique`) — يُعبّآن في `save()`.
- المصادقة تتمّ عبر **HMAC** فعلاً: `CustomUserManager.get_by_natural_key()` + `HMACAuthBackend` يبحثان بالـHMAC.
- `get_national_id_decrypted()` موجودة. (نفس النمط لـ`phone` — صريح أيضاً.)

## 2. إعادة تقييم الخطورة
- التصنيف الأصلي: **متوسطة** (الاستغلال يتطلّب اختراق القاعدة).
- **مُخفَّضة الآن:** الناقل الأخطر (النسخ الاحتياطية الصريحة) صار **مشفّراً AES-256** (commit 6d5d9ce). المتبقّي = نصّ صريح في القاعدة الحيّة فقط، ويتطلّب اختراقاً عميقاً، ودور التطبيق `shschool_app` يحتاج قراءته للدخول (فـcolumn-grants لا تنفع).
- **الخلاصة:** القيمة الأمنية الإضافية صارت محدودة مقابل خطر تنفيذيّ مرتفع. **قابل للتأجيل بأمان**؛ إن نُفِّذ فبالخطة أدناه فقط.

## 3. الخطة المُتدرّجة (expand/contract — بلا توقّف، قابلة للعكس)

### المرحلة 0 — تحضير (بلا تغيير سلوكي)
- migration: تعبئة `national_id_hmac` لأي سجلّ ناقص (idempotent)، ثم **فرض `unique=True`** عليه (شرط ليصبح `USERNAME_FIELD`). تحقّق من عدم وجود تصادمات HMAC قبل القيد.
- نشر + مراقبة. **rollback:** إزالة قيد unique.

### المرحلة 1 — تحصين مسار المصادقة (قبل أي تبديل)
- تأكيد أن `HMACAuthBackend.authenticate()` يُجزّئ النصّ المُدخَل → HMAC → بحث (لا يعتمد على `national_id` الصريح إطلاقاً).
- تأكيد كل مسارات الدخول: نموذج الدخول، استرجاع كلمة المرور، إنشاء مستخدم، TOTP، admin.
- **اختبار شامل على staging** قبل المتابعة. **rollback:** لا تغيير DDL بعد.

### المرحلة 2 — تبديل `USERNAME_FIELD`
- `USERNAME_FIELD = "national_id_hmac"` + جعل `national_id` **nullable**.
- تحويل كل مراجع `user.national_id`:
  - عرض → `get_national_id_decrypted()`.
  - بحث/lookup → HMAC.
  - `__str__`، forms، `create_user`، المصانع (factories)، الاستيراد/التصدير.
- نشر + **اختبار دخول حيّ فوري**. **rollback:** إرجاع `USERNAME_FIELD` (الحقل الصريح ما زال موجوداً nullable).

### المرحلة 3 — تطهير النصّ الصريح
- بعد التأكّد من استقرار المرحلة 2 (أيام): migration يُفرّغ (`NULL`) عمود `national_id` (مع إبقاء `national_id_encrypted`).
- (لاحقاً) حذف العمود نهائياً بعد فترة أمان.
- **rollback:** إعادة التعبئة من `national_id_encrypted` عبر `get_national_id_decrypted()`.

### كرّر نفس المراحل لـ`phone` (نفس النمط، أقلّ حساسية).

## 4. الاختبار الإلزامي قبل كل نشر
دخول · استرجاع كلمة مرور · إنشاء مستخدم · TOTP · admin · forms · بحث الطلاب · الاستيراد/التصدير · seed.

## 5. التوصية
